# ربات تلگرام مترجم PDF انگلیسی → فارسی

نسخهٔ سروری پروژهٔ مترجم PDF: کاربر فایل PDF انگلیسی را به ربات می‌دهد و همان فایل را
با حفظ چیدمان (موقعیت/اندازه/بولد/رنگ متن) و چیدمان آینه‌ای راست‌به‌چپ به فارسی تحویل می‌گیرد.

- ربات تلگرام: `@PDFTransla_bot`
- موتور ترجمه: **Top Tools AI** (مدل `Top-Tools-Ai` — ۱۰ میلیون توکن در روز رایگان) + جایگزین Groq
- اجرا: **GitHub Actions** (ریپوی عمومی = دقایق Actions نامحدود و رایگان)
- مخزن: `https://github.com/irbiolop/pdf-translator-bot`

## معماری

| جزء | نقش |
|---|---|
| `bot.py` | پولینگ طولانی تلگرام، صف ترجمه، پنل ادمین، force join، آمار، گزارش مصرف توکن |
| `translator_core.py` | موتور ترجمهٔ PDF (هر سرویس سازگار OpenAI) + آینه‌سازی RTL + مقیاس یکنواخت + **ترجمهٔ موازی بچ‌ها** + شمارش توکن |
| `.github/workflows/bot.yml` | اجرای ربات روی Actions با زنجیرهٔ ری‌استارت ۲۴/۷ |
| `.github/workflows/repo-keepalive.yml` | کامیت هر ۵ روز (ضد خاموشی ۶۰ روزهٔ workflowهای cron) |
| `data/state.json` | تنظیمات ادمین + آمار کاربران + توکن مصرفی؛ با Contents API در همین مخزن ذخیره/بازیابی می‌شود |

## موتور ترجمه و سرعت

دو سرویس سازگار با OpenAI پشتیبانی می‌شوند و ادمین از پنل بین‌شان سوئیچ می‌کند:

| سرویس | مدل پیش‌فرض | سهمیه | حالت سرعت |
|---|---|---|---|
| **Top Tools AI** (پیش‌فرض) | `Top-Tools-Ai` | ۱۰M توکن/روز، ~۴۵RPM، ۵ درخواست همزمان | **موازی ×۲ تا ×۴ ورکر** + فاصله‌گذار نرخ |
| Groq (جایگزین) | `openai/gpt-oss-120b` | ~۸هزار توکن/دقیقه، ۳۰RPM | پشت‌سرهم با مکث ۱۵–۴۰ ثانیه |

- ترجمهٔ موازی: بچ‌های صفحات مختلف همزمان به سرویس می‌روند (تا ۴ ورکر) → یک فایل
  ۳۰ صفحه‌ای به‌جای ~۱۰ دقیقه، در حدود ۲–۳ دقیقه تمام می‌شود.
- ادمین می‌تواند مدل را از فهرست Top Tools AI عوض کند:
  `Top-Tools-Ai`، `GLM-5.3-Flash`، `DeepSeek-V4-Flash`، `DeepSeek-V4.1-Flash`،
  `MiMo-V2.5`، `MiniMax-M3`، `GLM-5.3`، `Kimi-K2.6`.
- بعد از هر فایل، **گزارش مصرف توکن** (ورودی/خروجی/مجموع + تعداد درخواست + مدت + کاربر)
  به ادمین پیام می‌شود و در آمار هم تجمیع می‌شود.

## اجرای ۲۴/۷ روی GitHub Actions (نحوهٔ دور زدن سقف ۶ ساعت)

هر جاب GitHub-hosted حداکثر **۶ ساعت** می‌تواند زنده باشد (سقف سخت GitHub). راه‌حل این ریپو:

1. workflow `bot.yml` ربات را با `RUN_MAX_MINUTES=300` اجرا می‌کند؛
2. ربات بعد از ~۵ ساعت **تمیز** خارج می‌شود (اول ترجمهٔ در جریان تمام می‌شود، بعد وضعیت کامیت می‌شود)؛
3. همان workflow بلافاصله با `workflow_dispatch` چرخهٔ بعدی را می‌سازد → حلقهٔ بی‌پایان؛
4. کرون `37 1,7,13,19 * * *` فقط پشتیبان است (اگر زنجیره قطع شده باشد آن را از نو می‌سازد)؛
5. گام «جلوگیری از اجرای موازی» با `gh run list` مطمئن می‌شود فقط یک نمونه فعال باشد؛
   اگر دو نمونه شوند، تلگرام 409 می‌دهد و نمونهٔ اضافه با کد خروج ۳ خودش را جمع می‌کند.

نتیجه: آپ‌تایم ۲۴/۷ با گپ ~۱–۲ دقیقه‌ای هر ۵ ساعت. ریپو باید **عمومی** بماند
(ریپوی عمومی = دقایق Actions رایگان و نامحدود؛ خصوصی بودن یعنی مصرف ۲۰۰۰ دقیقهٔ ماهانه در ۱٫۵ روز).

**روشن/خاموش کردن ربات:** تب Actions → «Bot (24/7)» → Run workflow (روشن)،
یا Disable workflow (خاموش). کامیت‌های `data/state.json` که خود ربات می‌زند باعث می‌شود
ریپو هرگز ۶۰ روز بی‌تحرک نماند و کرون‌ها خاموش نشوند.

## پنل ادمین (داخل ربات)

به ربات دستور `/admin` بدهید (فقط برای ایدی عددی ادمین):

- 📊 آمار کاربران (کل، فعال ۲۴ ساعت، توکن مصرفی، برترین کاربران)
- 🤖 سرویس: سوئیچ بین Top Tools AI و Groq
- 🧠 مدل: چرخش بین مدل‌های سرویس فعال
- ⚡ سرعت ترجمه: موازی ×۴ / ×۳ / ×۲ (Top Tools AI) یا مکث ۱۵/۲۵/۴۰ ثانیه (Groq)
- 📄 سقف صفحهٔ هر فایل (۱ تا ۵۰۰)
- 📢 کانال اجباری: روشن/خاموش + تغییر کانال (`@channel` یا `-100...`)
  - توجه: برای پرسیدن عضویت، ربات باید در آن کانال **ادمین** باشد.
- 💾 ذخیرهٔ دستی وضعیت در GitHub

دستور `/ping` وضعیت **همهٔ سرویس‌ها** را یکجا تست و جدول می‌دهد.

## فیلورور خودکار و مقاوم‌سازی خطا

- اگر سرویس فعال قطع/مسدود باشد (مثل `provider_http_401` گیت‌وی Top Tools AI، کلید نامعتبر، ۴۰۳ دسترسی یا مدلِ یافت‌نشده)، ربات **خودکار** با سرویس بعدیِ دارای کلید ادامه می‌دهد و کاربر فقط یک پیام «ادامه با سرویس جایگزین» می‌بیند.
- قطعیِ هر سرویس حداکثر هر ۳۰ دقیقه یک‌بار به ادمین هشدار داده می‌شود (ضد هرج‌ومرج).
- اگر سرویس هیچ صفحه‌ای را ترجمه نکند (موج ۵xx)، به‌جای تحویل فایلِ دست‌نخورده با ظاهر موفقیت، خطای فیلورورپذیر پرتاب می‌شود.
- پیام‌های خطا برای کاربر کوتاه و فارسی‌اند؛ بدنهٔ خام انگلیسی سرویس نمایش داده نمی‌شود.

## کاهش حجم فایل خروجی

ذخیرهٔ نهایی هر فایل با فشرده‌سازی کامل انجام می‌شود:

1. `subset_fonts` — فقط نویسه‌های استفاده‌شده از فونت فارسی نگه داشته می‌شود (فونت کامل وزیرمتن صدها KB است)
2. `rewrite_images` — تصاویر بالای ۱۵۰DPI به ۱۲۰DPI با JPEG کیفیت ۷۰ بازفشرده می‌شوند (اسکن‌های حجیم چندده‌برابر کوچک می‌شوند)
3. ذخیره با `garbage=4 + clean + deflate_fonts/images` — اشیای بلااستفاده و نسخه‌های تکراری حذف می‌شوند

حجم فایل خروجی در کپشن تلگرام نمایش داده می‌شود؛ خروجی‌های بالای ~۴۹.۵MB (سقف Bot API) با پیام شفاف رد می‌شوند و صفحاتی که سرویس نتوانست ترجمه کند در کپشن اعلام می‌شوند (متن اصلی‌شان حفظ می‌ماند).

## آینه‌سازی گرافیک و جدول‌ها

متن به‌تنهایی آینه نمی‌شود؛ کل چیدمان راست‌به‌چپ می‌شود:

- **ترسیم‌های برداری** (شبکهٔ جدول‌ها، کادرها، خطوط، هایلایت‌ها) همراه با متن آینه می‌شوند تا کادرها و جدول‌ها دقیقاً دور متن آینه‌شده بمانند.
- **تصاویر** به موقعیت آینه‌ای منتقل می‌شوند ولی محتوای خودشان برعکس نمی‌شود — اسکرین‌شات‌ها و متنِ داخل عکس سالم می‌ماند.
- **جدول‌ها:** سلول‌های هر ردیف قبل از ترجمه از هم جدا می‌شوند (تشخیص جدول با `find_tables`) تا ترجمهٔ هر سلول دقیقاً داخل خانهٔ آینه‌شدهٔ خودش بنشیند و از خطوط شبکه بیرون نزند.
- **لینک‌ها** هم به ناحیهٔ آینه‌شده منتقل می‌شوند.
- گسترش کادرهای متنیِ باریک اگر به بلوک مجاور (مثل سلول کناری جدول) سرریز شود لغو می‌شود تا متن از خانه بیرون نزند.
- صفحات چرخیده یا با CropBox غیراستاندارد، با روش قدیمی (فقط آینه‌سازی متن) پردازش می‌شوند تا خراب نشوند.

## Secrets (Settings → Secrets and variables → Actions)

| کلید | توضیح |
|---|---|
| `TELEGRAM_TOKEN` | توکن ربات |
| `TT_API_KEY` | کلید Top Tools AI (سرویس پیش‌فرض) |
| `GROQ_API_KEY` | کلید Groq (سرویس جایگزین) |
| `ADMIN_ID` | ایدی عددی ادمین |

(`GITHUB_TOKEN` و `GITHUB_REPOSITORY` به‌صورت خودکار توسط Actions تزریق می‌شوند.)

## استقرار جایگزین روی Render (اختیاری)

`render.yaml` و وب‌سرور `/health` حفظ شده‌اند؛ اگر بعداً پلن رایگان Render را فعال کردید
کافیست سرویس را از همین ریپو بسازید و `keepalive-render.yml` را از تاریخچهٔ گیت برگردانید.
حالت Render بدون `RUN_MAX_MINUTES` ران می‌شود (بدون سقف چرخه).

## محدودیت‌های سرویس‌ها (اکتبر ۲۰۲۶)

**Top Tools AI:** سهمیهٔ `Top-Tools-Ai` ده میلیون توکن در روز است (≈ ۲٬۵۰۰ تا ۴٬۰۰۰ صفحه)
و سقف کلی ~۴۵ درخواست در دقیقه و ۵ درخواست همزمان دارد؛ ربات با فاصله‌گذار نرخ و
۴29-retry داخل این سقف می‌ماند. مدل‌های دیگر نیازمند اشتراک/موجودی خوش‌آمدگویی هستند
و اگر فعال نباشند سرویس 403 می‌دهد (ربات پیام شفاف به کاربر می‌دهد).

**Groq (جایگزین):** سقف‌ها مدل‌به‌مدل و در سطح سازمان است: ~۳۰ درخواست/دقیقه،
~۱٬۰۰۰ درخواست/روز، ~۸٬۰۰۰ توکن/دقیقه، ~۲۰۰٬۰۰۰ توکن/روز (≈ ۱۰۰–۱۵۰ صفحه در روز).
مدل‌های Llama از تیر فری حذف شده‌اند.

## امنیت

- هیچ کلیدی داخل کد نیست؛ توکن‌ها در Secrets ریپو هستند و فقط به محیط جاب تزریق می‌شوند.
- `GITHUB_TOKEN` مورد استفادهٔ ربات، توکن موقت و محدود به همین ریپوی Actions است.
- توکن‌هایی که در گفتگو برای راه‌اندازی منتقل شدند، پس از راه‌اندازی بهتر است چرخانده شوند
  (GitHub → Settings → Developer settings، BotFather → /revoke، Groq → console).
