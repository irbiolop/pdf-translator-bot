# ربات تلگرام مترجم PDF

نسخهٔ سروری پروژهٔ مترجم PDF: کاربر فایل PDF را به ربات می‌دهد و همان فایل را
با حفظ چیدمان (موقعیت/اندازه/بولد/رنگ متن، عکس‌ها و جدول‌ها) به زبان مقصد
(پیش‌فرض: فارسی، راست‌چین و آینه‌ای) تحویل می‌گیرد.

- ربات تلگرام: `@PDFTransla_bot`
- موتور ترجمه: **OpenCode Zen** (مدل‌های رایگان) از طریق خودِ **CLI اوپن‌کد** — فقط موقع ترجمه روشن و بعد از کار خاموش می‌شود
- اجرا: **GitHub Actions** (ریپوی عمومی = دقایق Actions نامحدود و رایگان)
- مخزن: `https://github.com/irbiolop/pdf-translator-bot`

## معماری

| جزء | نقش |
|---|---|
| `bot.py` | پولینگ طولانی تلگرام، صف ترجمه، پنل ادمین، مجوز کاربران (تأیید ادمین)، MTProto فایل‌های بزرگ، آمار و گزارش مصرف توکن |
| `translator_core.py` | موتور ترجمهٔ PDF (مسیر اصلی: OpenCode CLI / مسیر تست: هر سرویس سازگار OpenAI) + آینه‌سازی RTL + مقیاس یکنواخت + ترجمهٔ موازی بچ‌ها |
| `.github/workflows/bot.yml` | اجرای ربات روی Actions با نصب opencode و زنجیرهٔ ری‌استارت ۲۴/۷ |
| `data/state.json` | تنظیمات ادمین + کاربران مجاز + آمار؛ با Contents API در همین مخزن ذخیره/بازیابی می‌شود |

## موتور ترجمه: OpenCode Zen از طریق CLI

ردهٔ رایگان Zen فقط به درخواستِ «از داخل خودِ OpenCode» جواب می‌دهد؛ پس ربات
بجای فراخوانی مستقیم API، ترجمه را به `opencode run` می‌سپارد (ترافیک واقعی
OpenCode → مدل‌های رایگان کار می‌کنند):

- **روشن/خاموش خودکار:** فقط موقع ترجمه `auth.json` نوشته می‌شود و بلافاصله بعد
  از پایان کار حذف می‌شود؛ بین ترجمه‌ها هیچ کلیدی روی دیسک/شبکه نیست (ضد بن).
- هر بچ یک `opencode run -m opencode/<مدل> --pure --format json` است؛ پاسخ JSON
  و مصرف توکن از رویدادهای خروجی استخراج می‌شود (`cost=0` برای مدل رایگان).
- سرعت پیش‌فرض «متعادل»: ۲ فراخوانی همزمان با فاصلهٔ ۴ ثانیه — الگوی مصرف انسانی.
- ادمین با `/model` از بین مدل‌های **رایگان** (پسوند `-free` + `big-pickle`)
  مدل را انتخاب می‌کند؛ پیش‌فرض `deepseek-v4.1-flash-free`.
- با `/lang` زبان مبدأ (خودکار/انگلیسی/عربی/فرانسوی/آلمانی/ترکی/روسی/چینی/…)
  و زبان مقصد (فارسی/انگلیسی/عربی/ترکی) انتخاب می‌شود؛ برای مقصد راست‌به‌چپ
  چیدمان آینه‌ای و برای چپ‌به‌راست چیدمان عادی اعمال می‌شود.

## مجوز کاربران (تأیید ادمین)

- کاربران جدید **پیش‌فرض غیرمجازند**: هر پیامشان پاسخ «شما مجاز نیستید» می‌گیرد
  و یک پیام با دکمه‌های «✅ تأیید / ❌ رد» به ادمین می‌رود.
- بعد از تأیید، کاربر بلافاصله پیام خوش‌آمد می‌گیرد و می‌تواند فایل بفرستد.
- فهرست مجازها در `data/state.json` ماندگار است؛ با `/allow <آیدی>` و
  `/deny <آیدی>` هم می‌شود دستی افزود/حذف کرد. متغیر `ALLOWED_USERS`
  (repo variable، کاما-جدا) فهرست اولیه را می‌سازد.
- ادمین همیشه مجاز است. `/id` برای کاربران غیرمجاز هم کار می‌کند تا آیدی‌شان را بفرستند.

## فایل‌های بزرگ با MTProto (Telethon)

- دانلود: تا ~۲ گیگابایت — فایل‌های بالای ۱۹MB از Bot API رد نمی‌شوند و از
  مسیر MTProto دانلود می‌شوند.
- آپلود: خروجی بالای ۴۹.۵MB هم با MTProto برمی‌گردد (سقف ۵۰MB Bot API دور زده می‌شود).
- کلاینت Telethon در ترد جدا با `API_ID`/`API_HASH` ربات لاگین می‌کند؛
  access-hash کاربران از خود آپدیت‌ها کش می‌شود.

## اجرای ۲۴/۷ روی GitHub Actions

هر جاب GitHub-hosted حداکثر ۶ ساعت زنده است؛ راه‌حل این ریپو:

1. `bot.yml` ربات را با `RUN_MAX_MINUTES=300` اجرا و opencode را نصب می‌کند؛
2. ربات بعد از ~۵ ساعت تمیز خارج می‌شود (اول ترجمهٔ در جریان، بعد کامیت وضعیت)؛
3. همان workflow بلافاصله چرخهٔ بعدی را dispatch می‌کند → حلقهٔ بی‌پایان؛
4. کرون `37 1,7,13,19 * * *` پشتیبان است؛ گام «جلوگیری از اجرای موازی» هم هست.

نتیجه: آپ‌تایم ۲۴/۷ با گپ ~۱–۲ دقیقه‌ای هر ۵ ساعت. ریپو **عمومی** بماند
(دقایق Actions رایگان نامحدود).

**روشن/خاموش کردن ربات:** تب Actions → «Bot (24/7)» → Run workflow (روشن)،
یا Disable workflow (خاموش).

## پنل ادمین (داخل ربات)

`/admin` (فقط ادمین):

- 📊 آمار کاربران (کل، فعال ۲۴ ساعت، توکن مصرفی، برترین کاربران)
- 🧠 مدل: فهرست مدل‌های رایگان OpenCode با دکمهٔ انتخاب
- ⚡ سرعت: موازی ×۳ (سریع) / ×۲ (متعادل) / تک‌کارگر (محتاط)
- 🌐 زبان مبدأ/مقصد
- 🛡 کاربران مجاز: فهرست + شمارنده
- 📄 سقف صفحه (۱ تا ۲۰۰۰ — فایل‌های خیلی بزرگ باید تا پایان چرخهٔ جاری جا شوند، وگرنه ربات زمان چرخهٔ بعد را اعلام می‌کند) • 📢 کانال اجباری • 🔗 کانال • 💾 ذخیرهٔ دستی وضعیت

دستورهای ادمین: `/model` `/lang` `/allow` `/deny` `/ping` (تست واقعی ترجمه
با روشن/خاموش‌کردن موقت کلید).

## تایپوگرافی خروجی (فیدبک‌محور)

- فونت فارسی ~۱۰٪ کوچک‌تر از متن اصلی درج می‌شود (`FONT_SCALE_FACTOR=0.9`) — وزیرمتن در هم‌اندازه، بزرگ‌تر دیده می‌شود.
- فاصلهٔ خطوط حداقل ۱٫۵۵ و ~۱۲٪ بازتر از PDF اصلی (`MIN_LEADING=1.55`) — فارسی نفس بیشتری می‌خواهد.
- راست‌چین واقعی: `dir="rtl"` روی هر بلوک + چینش راست؛ وسط‌چین‌ها حفظ می‌شوند.

## آینه‌سازی گرافیک و جدول‌ها

- ترسیم‌های برداری (شبکهٔ جدول‌ها/کادرها) همراه متن آینه می‌شوند؛
- تصاویر به موقعیت آینه‌ای منتقل ولی محتوایشان برعکس نمی‌شود؛
- سلول‌های جدول با `find_tables` جدا و مستقل ترجمه می‌شوند (متن از خانه بیرون نمی‌زند)؛
- لینک‌ها هم آینه می‌شوند؛ صفحات چرخیده/CropBox غیراستاندارد با روش محافظه‌کارانه.

## کاهش حجم فایل خروجی

`subset_fonts` + `rewrite_images` (۱۵۰→۱۲۰DPI، JPEG ۷۰) + ذخیرهٔ
`garbage=4/clean/deflate` — حجم در کپشن نمایش داده می‌شود.

## Secrets و Variables

| کلید | توضیح |
|---|---|
| `TELEGRAM_TOKEN` | توکن ربات |
| `OPENCODE_API_KEY` | کلید OpenCode Zen (`oc_sk_...`) — فقط موقع ترجمه استفاده می‌شود |
| `TELEGRAM_API_ID` / `TELEGRAM_API_HASH` | اعتبار MTProto برای فایل‌های بزرگ |
| `ADMIN_ID` | آیدی عددی ادمین |
| `ALLOWED_USERS` (Variable) | فهرست اولیهٔ کاربران مجاز، کاما-جدا (اختیاری) |

(`GITHUB_TOKEN` و `GITHUB_REPOSITORY` خودکار تزریق می‌شوند.)

## محدودیت‌ها (اکتبر ۲۰۲۶)

- ردهٔ رایگان OpenCode Zen فقط از داخل خودِ OpenCode کار می‌کند (تأیید شد)؛
  فراخوانی مستقیم REST با کلید `oc_sk_` روی مدل‌های `-free` خطای `FreeTierError` می‌دهد — به همین دلیل ترجمه از طریق CLI است.
- مدل‌های `-free` هزینهٔ صفر دارند (`cost=0`)؛ مدل‌های غیر رایگان موجودی لازم دارند.
- سقف نرخ مدل‌های رایگان اعلام‌شده نیست؛ ربات با ورکر محدود + فاصله‌گذاری + retry محافظه‌کارانه رفتار می‌کند.

## امنیت

- هیچ کلیدی داخل کد نیست؛ توکن‌ها در Secrets ریپو هستند و فقط به محیط جاب تزریق می‌شوند.
- کلید OpenCode بین ترجمه‌ها از دیسک حذف می‌شود (فقط در حافظهٔ جاب در حال اجراست).
- `GITHUB_TOKEN` مورد استفادهٔ ربات، توکن موقت و محدود به همین ریپوی Actions است.
